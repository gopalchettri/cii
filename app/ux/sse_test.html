TSG Live Tracer

Watches a session's live events and maps every change to the pipeline stage that caused it. Everything in the timeline is runtime data; the stage it proves comes from the code's transition rules.
How the stream works (app/api/routers/events.py): GET /v1/sessions/{id}/events sends one event name, session.updated, carrying the same RunBoard JSON as GET /v1/sessions/{id} (session_status and progress: threats, scenarios, controls, overall, timings, error_message, last_next_set, last_regen, scenario_count); GET /v1/sessions/{id}/scenarios/{id}/treatment-plan/events sends remediation.updated carrying RemediationStatus. Each stream sends the current status at once on connect, then only bodies that changed; it re-checks every 30 s while a job is queued or running, and FastAPI writes a : ping comment after 15 s of silence. Publishes are best effort, so the backstop poll stays on. EventSource cannot send the auth headers, so the stream is read with fetch().
