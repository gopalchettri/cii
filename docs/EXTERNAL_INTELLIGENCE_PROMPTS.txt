WHICH PROMPT WRITES A SCENARIO: EXTERNAL INTELLIGENCE ON vs OFF
================================================================

SHORT VERSION
Two writer prompts exist. One switch decides which one runs.

  Switch OFF -> the ORIGINAL prompt (the TSG as it was)
  Switch ON  -> the EVIDENCE-STORY prompt (new)

The switch is ON only when BOTH are true:
  1. EXTERNAL_INTELLIGENCE_ENABLED=true in the env file (master lock), and
  2. the runtime admin flag is on (PUT /v1/tsg/intel/switch, cached about 60 seconds).
Default is OFF.


PROMPT FILES (all under C:\GopalChettri\Projects\desc-ai-modules\cii\)
----------------------------------------------------------------------
OFF  original writer prompt
     app/engine/scenarios/writing/writing_prompts.py          (function writer_prompt, unchanged)

ON   evidence-story writer, user prompt (builds BRIEF + the EVIDENCE block)
     app/engine/external_intelligence/story/evidence_story_prompts.py   (story_writer_prompt)
ON   evidence-story writer, system prompt text (storytelling and [n] marker rules)

ON   plan check for stories
     evidence_story_prompts.py (story_plan_check_prompt) + STORY_PLAN_CHECK_SYSTEM_PROMPT in evidence_story_texts.py

WHERE THE CHOICE IS MADE
     app/engine/scenarios/writing/scenario_writer.py, line 40:
       prompt = story_writer_prompt(brief) if _is_story(brief) else writer_prompt(brief)
     The style itself is decided once per batch in app/worker/tasks/writing.py (access.writer_style()).


STEP BY STEP: SWITCH OFF
------------------------
1. A writing batch starts. writer_style() returns ORIGINAL.
2. No evidence search runs. The brief has no evidence.
3. scenario_writer.py picks writer_prompt (writing_prompts.py).
4. The original exact rules and plan check run.
5. The scenario is saved with prompt_version "writer-1". No evidence keys are stored.
Result: a short plain scenario (about 65 words), identical to the original TSG.


STEP BY STEP: SWITCH ON
-----------------------
1. A writing batch starts. writer_style() returns EVIDENCE_STORY (for the whole batch).
2. The evidence search runs for the batch's threats
   (app/worker/external_intelligence/evidence_at_write.py). Results are saved on the plan.
3. brief_builder.py copies the threat's evidence into the writer brief.
4. scenario_writer.py picks story_writer_prompt. The evidence goes into a separate block
   "EVIDENCE (untrusted data)" between begin/end delimiters. Facts are numbered and cleaned:
   no ids, no links, nothing that reads like an instruction. The model never sees titles,
   links, CVE ids or technique ids.
5. The model writes the story with [1], [2] markers.
6. The story rules (evidence_story_rules.py) and the story plan-check prompt run. A problem
   gets one rewrite; the better draft is kept.
7. The scenario is saved with prompt_version "writer-evidence-1" plus the evidence panel
   (numbered entries the markers point to), evidence_mode, applicability and the search audit
   (app/engine/scenarios/writing/scenario_record.py, _evidence_content).
Result: a longer story (THREAT_SCENARIO_WORD_LIMIT words, default 300-400; G226) with markers and an evidence panel.


IMPORTANT RULES
---------------
* With ON, EVERY scenario in the batch uses the evidence-story prompt, even a threat for which
  no evidence was found. That scenario is written without [n] markers (evidence_mode "inferred").
* The style is decided once per batch, so a batch never mixes the two writers.
* A flip of the runtime switch takes effect on the next batch (about 60 seconds, the flag is cached).
* A regenerate reads the saved prompt_version and keeps that scenario's style.
* The rules and plan check follow the same choice: OFF uses the original ones, ON the story ones.
* writing_prompts.py (the original, owner-approved prompts) is NOT modified by this feature. The owner
  changed its rules on 2026-10-13 (G220, OFF): simple precise English for GRC and business readers, an opening
  from the scenario's own threat angle (rule 14), facts kept apart from assumptions, no external source or
  invented intelligence. Still 3 to 4 sentences; version stays writer-1.
* The evidence story (owner, 2026-10-13, ON only): technically detailed but safe (the technique, the access,
  the affected component and the impact in precise plain words; no commands, code or exploit recipes, rule 9),
  opening from the scenario's own threat angle, never a general description of the asset (rule 16), and only
  a marked claim counts as real-world intelligence (rule 13). Prompt version stays writer-evidence-1.
